Deployment providers, one menu bar.

DeployBar keeps provider-specific polling and discovery behind a unified status model, so each service can show the same clean snapshot in the popover.

Vercel
Project, branch, environment, team, and recent deployment discovery.
Railway
GraphQL-backed deployment polling for projects, services, and environments.
Netlify
Site deploys with optional context and branch filtering.
Render
Service deployment status from the Render REST API.
Cloudflare Pages
Pages projects and deployments by account and project name.
DigitalOcean
App Platform deployments across accessible apps.
Heroku
Release activity mapped into the same deployment timeline.
GitHub
Repository deployments plus the latest status from each deployment.
GitLab
Project deployments for GitLab.com and self-managed instances.

Built for quiet deployment awareness.

The app favors local state, provider-level isolation, and a compact native interface that stays useful during repeated deploy cycles.

Focused snapshots

Active, waiting, failed, and healthy deployments roll up into one readable status.

Native notifications

macOS alerts fire when deployments become ready, fail, cancel, or disappear.

Credential isolation

Provider tokens stay in Keychain while non-secret settings remain local JSON.

Provider diagnostics

Refresh issues, stale data, and authentication failures surface without leaking secrets.

Build it from source.

DeployBar is a Swift Package with a native SwiftUI and AppKit shell. No Electron runtime, no backend account, and no hosted credential sync.

  • Tokens are stored only in Keychain under the DeployBar token service.
  • Settings are kept under Application Support as local JSON.
  • The app requests notification permission, not Full Disk Access, Accessibility, or Screen Recording.
